# 미확정 9건: 원인 분석과 두 번째 개선

2026-11-15. 앞서 추가 표본 17건 중 미확정이던 9건을 원본 영상, 두 차선 모델의 곡선과 유효 범위, 차량 검출 상자까지 역추적했다. **2건은 경계 근거를 확보한 배정, 1건은 잠정 배정으로 바뀌었으며 6건은 미확정으로 남았다.** 잠정 배정은 속도·대기열·거리 안내 계산에 사용하지 않는다.

## 먼저 고친 검증 오류

이전의 하단 접점 근처 상자 매칭은 혼잡 영상의 먼 흰색 버스 2건을 바로 앞 승용차 상자와 잘못 연결했다. 따라서 이전 보고의 ‘검출 대응 실패 0건’은 잘못된 수치였다. 버스 전체 상자를 원본에 표시하고 IoU 0.35 이상으로 매칭하도록 수정했다. 같은 수정 기준으로 이전 구현을 다시 평가하면 **8건 배정 / 7건 차로 미확정 / 2건 검출 대응 실패**다. 종전 ‘9건 미확정’의 분류가 이렇게 정정된다. 배정 성공 8건에는 변화가 없다.

기존 표본 파일과 결과는 보존했다. `lane-refinement-labels.json`은 기존 17건 중 버스 2건에 `referenceBox`를 추가한 수정본이다. 새 비교 프레임의 먼 버스에도 동일하게 전체 상자 기준을 적용했다. 다른 차량은 기존 접점 기준이며, 모든 차량의 정식 객체 검출 평가를 수행한 것은 아니다.

## 코드 변경

1. **차량별 차선 결합.** 기존에는 구조 모델이 프레임에서 내 차로를 찾으면 YOLOP를 생략했다. 현재는 두 모델을 실행하고, 구조 모델이 판단하지 못한 차량에 한해 페인트 경계를 확인한다. 겹치는 내 차로 경계의 범위가 높이 10% 이상이고 5개 위치에서 각 경계 차이가 너비 4% 미만이어야 보완한다. 둘이 명시적으로 다른 차로를 반환하면 보류한다.
2. **검출기 보강.** YOLO11n/960에서 YOLO11s/1280으로 변경했다. 같은 물체가 car/truck 등 서로 다른 종류로 중복 집계되는 것을 줄이도록 차종을 구분하지 않는 NMS를 사용한다. 작은 표본에서 버스 두 건 모두 검출됐지만, 새 프레임의 버스 한 건은 여전히 검출 대응에 실패했다.
3. **제한된 잠정 배정.** EGO에 한해 차선 상단을 영상 높이 3% 이내로 연장하고, 반대 경계는 1% 이내에 근거가 있어야 한다. 접점이 충분히 안쪽에 있고, 폭·곡률 안정성·페인트 경계 일치 조건을 만족해야 한다. `SHORT_RANGE_SUPPORTED_RECOVERY`, `metricEligible=false`로 명시한다. 이는 측정된 경계와 같은 수준의 근거가 아니다.
4. **판단 사유 기록.** `lane-analysis.json`의 차량마다 `reason`, `metricEligible`, `sideEvidence`를 저장한다. 내 차로 바깥이라는 근거를 정확한 인접 차로 번호로 집계하지 않는다.
5. **앱 표시·집계.** 잠정 배정은 차량 수에 포함하되 `provisionalCount`로 별도 전달하여 앱에 ‘잠정 배정 N대’라고 표시한다. 속도 계산 및 밀집 후보의 3대 조건에서는 제외한다. 검출 상자가 없으면 차량 검출 실패와 차로 미확정을 구분한다.

## 비교 결과

| 평가 표본 | 이전 | 개선 후 | 새 오분류 |
|---|---:|---:|---:|
| 문제를 분석한 17건 | 정답 배정 8건 | **10건 + 잠정 1건** | 0 |
| 그중 정확한 EGO/LEFT_1 표기 11건 | 정답 7건 | **8건 + 잠정 1건** | 0 |
| 기존 개발 표본 19건 | 정답 배정 10건 | **11건 + 잠정 1건** | 0 |
| 다른 4개 프레임의 새 표본 13건 | 정답 배정 6건 | **6건** | 0 |

17건의 전체 배정률은 잠정 포함 47.1% → 64.7%, 잠정을 제외하면 58.8%다. 개선 후 6건은 모두 차량은 검출됐으나 차로를 확정하지 못한 경우다. 새 13건에서는 차로 배정률 46.2%가 그대로이며 검출 대응 실패만 2건에서 1건으로 줄었다. **이번에 분석한 문제 사례에서는 개선됐지만 새로운 프레임에서 배정률 개선을 입증하지는 못했다.**

17건은 이번에 원인 분석과 수정에 사용했으므로 더 이상 보류 평가 세트라고 부르지 않는다. 새 13건은 수정 전 원본 프레임에 표시했고 결과를 본 뒤 임계값을 재조정하지 않았다. 모두 같은 두 영상의 인접 장면으로 독립적인 주행 환경 평가가 아니다. 오분류 0건도 일반적인 정확도 100%를 뜻하지 않는다. 기존 19건에는 접점 기준의 먼 차량 매칭 한계가 남으므로 보조 회귀 비교로만 사용한다.

YOLO11s 가중치는 [Ultralytics 공식 배포](https://github.com/ultralytics/assets/releases/download/v8.3.0/yolo11s.pt)를 사용하며 SHA-256은 `85A76FE86DD8AFE384648546B56A7A78580C7CB7B404FC595F97969322D502D5`다. 차선 모델은 첫 개선과 동일하다.

## 다음 개선에 필요한 근거

남은 6건 중 경계 자체가 없는 3건은 연석·중앙분리대·주행 가능 영역을 함께 인식하는 모델과 해당 도로의 차로 정답이 필요하다. 원거리 2건은 충분한 해상도 외에도 가려진 접점과 경계의 불확실성을 다뤄야 한다. 경계 부근 1건은 차량 바닥 접점/차체 폭과 시간별 이동을 함께 확인해야 한다. 이들을 현재 표본에 맞춰 강제로 배정하는 대신, 새로운 독립 영상과 동기화된 속도·자세 데이터를 확보한 뒤 평가해야 한다. 실제 속도 기반 정체 정확도와 미터 단위 준비 지점 오차는 여전히 미검증이다.

## 실행 검증

Python 검사 24개, Kotlin 단위 검사 19개, Android 계약·화면 연결 검사 5개가 통과했다. Android 화면 검사에는 실제 재생 파일의 ‘잠정 배정’ 표시도 포함한다. Pleos 활성 운전자 프로필 10에 개선 앱과 혼잡 영상 재생 파일을 설치했다.

혼잡 영상의 약 1초 간격 기록 10개에서 차로 배정 관측은 38/84건에서 47/113건으로 늘었지만, 새 관측 중 10건은 잠정 배정이다. 잠정을 제외한 배정은 37건이다. 따라서 전체 영상에서 확실한 배정량까지 늘었다고 주장하지 않는다. 같은 차량이 반복 포함된 관측이며, 정지 프레임 predict와 연속 영상 BoT-SORT track의 결과도 다를 수 있다. 왼쪽 차로의 밀집 후보는 5.7·6.7·7.7·8.7초에 표시됐고, EGO 잠정 배정은 후보 집계에서 제외됐다. metricObservations는 0으로 유지했다.

YOLO11s/1280과 두 차선 모델의 동시 실행으로 CPU 계산 비용이 증가했다. 현재 결과는 녹화 영상의 오프라인 분석이며, 차량 내 실시간 처리 성능 검증은 아니다.

정지 프레임 감사의 queueReview는 이제 `--video-results`로 출력 폴더를 명시한 경우에만 생성한다. 다른 버전의 영상 결과가 기본 경로에서 섞이지 않도록 수정했다.

KITTI 전체 영상은 18개 저장 시점, 차량 관측 138건 중 차로 배정 21건(잠정 0건 포함)이었다. 밀집 후보와 거리 기반 queue는 발생하지 않았다. 이전 20/111건과 비교해도 일반적인 성능 개선을 주장하기에는 근거가 부족하다.
